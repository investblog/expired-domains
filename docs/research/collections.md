# Коллекции доменов: как у конкурентов и что сделать лучше

Дата: 2026-11-19. К вопросу 4 раздела 13 [SPEC](../SPEC.md).

**Как собраны данные.** Всё взято из публичных страниц. Страницы Chrome Web Store
открывались через зеркала (chrome-stats, chromeboard, extscope). Про SpamZilla и
CatchDoms известно только по фрагментам из поиска. Ничего не устанавливалось.

## Что есть у других

**Ни у одного конкурента нет именованных коллекций, папок или проектов.** Сохранённые
домены в этой нише организуют четырьмя способами:

| Способ | Кто | Как это работает |
|---|---|---|
| Одна «избранная» таблица | expireddomains.net, Dynadot, GoDaddy Auctions, DomfoRat | Звёздочка в строке → один общий список. На expireddomains.net у любого списка есть фильтр «только Watchlist» |
| Избранное с заметками и тегами | CatchDoms (платный сервис; по описанию продавца) | Заметка и теги на домен |
| Скрыть строку | SpamZilla | Кнопка Hide убирает строку из выдачи |
| Автоматический список | NameGPS | «Smart Watchlist (Radar)» сам добавляет домены выше порога оценки; пользователь, судя по описанию, домены в него не выбирает |

Остальное:
- **Сохранённые фильтры** вместо сохранённых доменов: Domain Powertools, DomCop.
- **Один общий список из нескольких вкладок:** domainbear, снято из магазина в 2025 году.
- **Жалоб на работу со списками** в отзывах не найдено. У этих расширений 14–217
  пользователей и по 1–4 общих отзыва.

## Где можно сделать лучше

Все конкуренты дают либо один плоский список без статусов, либо поиск без сохранения.
Пользователю нужен рабочий процесс: собрать домены → отсеять → отобрать → выгрузить
отобранное. Ниже — как сделать его локально, без сервера и аккаунтов, до 10 000 доменов.

1. **Коллекции — это теги, а не отдельные хранилища.**
   - Запись на домен остаётся одна (раздел 6 SPEC). Тегов у домена может быть несколько
     (в SPEC — до 20).
   - Перемещать и копировать между коллекциями ничего не нужно, дубли невозможны.
   - Выгрузить коллекцию — значит поставить фильтр по тегу и нажать «Экспорт».
2. **Статус у каждого домена:** «новый», «отобран», «отклонён», «куплен».
   - «Отклонён» — это скрытие, как у SpamZilla, но без удаления. Если домен снова
     попадётся на другой странице, он останется отклонённым.
   - Повторный захват домена не меняет его статус, теги и заметку.
3. **Заметка** — свободный текст на домен, как у CatchDoms.
4. **«Экспортировать то, что видно».** Фильтры по статусу, тегу и списку-источнику
   складываются, и экспорт берёт ровно эту выборку. Ф14 уже работает так для текстового
   фильтра.
5. **Массовые действия.** Отметить несколько строк и поставить им тег или статус.
6. **Быстрый фильтр «Отобранные»** — аналог фильтра «только Watchlist» на сайте, к
   которому пользователи уже привыкли.
7. **Резервная копия JSON** всего накопления, вместе с тегами, статусами и заметками,
   и восстановление из неё. Синхронизации нет, и без копии всё теряется вместе с
   профилем браузера.

## Фильтры «только рабочие» (запрос пользователя 2026-11-20)

Сайт фильтрует выдачу только на своей стороне, по одному списку. Мы фильтруем накопление
сразу по всем спискам и с учётом времени. Расширение не делает запросов, поэтому всё
считается по сохранённым колонкам и по моменту захвата `lastSeen`.

**Главная трудность.** Время на сайте часто относительное: `32 days`, `Yesterday 13:59`,
`2h 59m` (колонки `changes`, `changetimer`, `endtime`). Через день такое значение уже
неверно. Решение — считать абсолютное время от момента захвата `lastSeen` при показе и
фильтрации; хранится только исходный текст (Д8, SPEC Ф24).

Часовой пояс у `Yesterday 13:59` неизвестен **[не проверено]**, поэтому точность —
сутки.

| Фильтр | По каким данным | Пример значения в фикстурах |
|---|---|---|
| Свободен | `whois` / `whois2` = available | `available` 69, `registered` 6 |
| Данные свежие (не старше N ч) | `lastSeen` | — |
| Недавно освободился (≤ N дней) | `changes` → абсолютная дата | `32 days`, `Yesterday 13:59` |
| Скоро освободится (≤ N дней) | `enddate` в pending delete | `2026-11-21` |
| Аукцион ещё идёт | `endtime` → абсолютное время (`changetimer` — время с последнего изменения лота, не конец; SPEC Ф24) | `5h 33m`, `1d 14h 45m` |
| Качество: BL ≥, DP ≥, возраст по архиву, записей в архиве ≥ | `bl`, `domainpop`, `abirth`, `aentries` | `93.2 K`, `4`, `2019`, `41` |
| Имя: длина ≤, зона, без цифр и дефисов | имя домена | — |
| Статус, тег, список-источник | наши поля | — |

**Предустановки** — сохраняемые наборы условий, как сохранённые фильтры у Domain
Powertools. Встроенных «Рабочих» две (решение 2026-11-20; на страницах аукционов нет
колонки `whois`, поэтому одна общая подборка не пропускала бы лоты):
- **«Рабочие — дропы»:** свободен, данные свежие, не отклонён и не куплен;
- **«Рабочие — аукционы»:** аукцион ещё идёт, данные свежие, не отклонён и не куплен.

**Если колонки нет.** Если у домена нет колонки, по которой стоит условие (домен из
списка без `whois`), он считается «неизвестно». Такой домен **не проходит** фильтр. В
счётчике фильтра видно, сколько доменов отсеяно по этой причине. Исключений нет: «аукцион
ещё идёт» без колонки `endtime` тоже не проходит (SPEC Ф25).

## Чего не делать

- Никакой автопагинации и «автопилота», как у NameGPS Auto Pilot и Domain Powertools
  AJAX pagination. FAQ сайта закрывает аккаунты за любые «program/script/tool/bot» и
  «data mining». Это противоречит и нашему инварианту I3.
- Не копировать домены в отдельные списки: вернутся дубли и придётся синхронизировать
  заметки между копиями.
- Не строить дерево папок: для 10 000 доменов хватает плоского списка тегов со
  счётчиками.
- Не удалять там, где пользователь имеет в виду «отклонить».

## Что это меняет в ТЗ

**Принято пользователем 2026-11-20 целиком** и внесено в SPEC, раздел 4.6 (Ф20–Ф27).
Окончательная схема — в SPEC; здесь кратко:

- **Запись `d:<domain>`** получает три поля, которые захват не перезаписывает:
  `status`, `tags[]` (до 20), `note` (до 1000 символов).
- **Абсолютное время** не хранится, а считается от `lastSeen` (Ф24): `stats` — снимок
  последнего захвата (Ф8).
- **Справочника тегов в `meta` нет:** счётчики тегов считает интерфейс по записям.
- **Одна мутация `update { domains, patch }`** для одного и многих доменов (Ф10, Ф23)
  вместо отдельных `setStatus` / `setTags` / `setNote`.
- **CSV** получает колонки `status`, `tags`, `note`.
- **Резервная копия JSON** — новое требование. Импорт CSV/TXT остаётся в бэклоге.
- **Подсветка на странице** строк, у которых уже есть статус, остаётся в бэклоге (TODO).
  С ней «отклонённые» домены будут видны сразу при листании.
