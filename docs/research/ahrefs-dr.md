# Ahrefs Domain Rating по ключу пользователя

Дата: 2026-11-20. Идея пользователя: пользователь вводит свой ключ Ahrefs, и расширение
проверяет DR накопленных доменов. **Принято** — [ADR-0004](../decisions/ADR-0004-ahrefs-dr-opt-in.md),
v1.1. Аудитория — прежде всего держатели платных аккаунтов Ahrefs.

## Факты (по документации Ahrefs на 2026-11-20)

- **Бесплатный эндпоинт DR** появился 2026-06-08.
  - С 2026-08-10 нужен ключ APIv3, но запросы бесплатны и не расходуют units.
  - С 2026-10-06 есть параметр `version` = `dr3` (по умолчанию) или `dr4`.
- **Кто может получить ключ — противоречие в документации:**
  - страница эндпоинта: ключ создаётся в бесплатном аккаунте Ahrefs;
  - общее введение в API: ключи только на платных тарифах и только у владельца или
    администратора.

  **[не проверено]** — нужно создать ключ в бесплатном аккаунте.
- **Запросы:**
  - `GET https://api.ahrefs.com/v3/public/domain-rating-free?target=<domain>`;
  - `POST` того же адреса с `{"targets": [до 1000], "version": "dr3"}`;
  - авторизация — заголовок `Authorization: Bearer <key>`.
- **Лимит.** В документации есть только общий лимит API — 60 запросов в минуту. Для
  этого эндпоинта отдельно не указан.
- **CORS.** Заголовков `Access-Control-Allow-*` нет. Из content script запрос не пройдёт,
  из background — пройдёт при host-разрешении на `https://api.ahrefs.com/*`.
- **Лицензия DR** (ahrefs.com/legal/domain-rating-license, 2026-06-11):
  - **можно** встраивать DR в свои продукты;
  - рядом с каждым показанным значением **обязательна** надпись «Domain Rating by Ahrefs»
    со ссылкой на https://ahrefs.com/;
  - **нельзя** перепродавать данные и собирать их массово в конкурирующую базу;
  - **нельзя** обходить лимиты;
  - доступ могут отозвать без предупреждения.
- **Условия пользования Ahrefs.** Учётные данные пользователь хранит сам. Модель «каждый
  вводит свой ключ» им соответствует: общего ключа нет.

## Что это меняет в продукте

Сейчас I1 и I5 запрещают любые сетевые запросы, а I4 — host-разрешения. Проверка DR —
первый случай, когда расширение что-то отправляет наружу: имена доменов уходят в Ahrefs.
Сайт expireddomains.net это не затрагивает: к нему расширение по-прежнему не обращается
(I2, I3).

Если брать, то так:

- **Включение — только по желанию пользователя.**
  - Разрешение `https://api.ahrefs.com/*` объявлено как необязательное:
    `optional_host_permissions` в MV3, `optional_permissions` в Firefox MV2.
  - Браузер спрашивает его, только когда пользователь включает функцию. При установке
    предупреждений по-прежнему нет.
- **Запрос — только по кнопке** «Проверить DR» для выбранных доменов. Пачками до 1000
  доменов, из background, с паузой при ответе 429.
- **Отправляются только имена доменов.** Статистика, теги и заметки не уходят.
- **Ключ:**
  - хранится в `storage.local`, не в `sync`;
  - не попадает в резервную копию JSON и в экспорт;
  - его можно удалить одной кнопкой.
- **Результат:**
  - поля `dr` и `drCheckedAt` в записи — пользовательские, захват их не меняет;
  - фильтр «DR ≥»;
  - колонка CSV `dr`;
  - рядом со значением в интерфейсе — «Domain Rating by Ahrefs» со ссылкой.
- **Переписать документы:**
  - I1, I4 и I5;
  - A1 и A8: запросы только к `api.ahrefs.com` и только после включения функции;
  - раздел «Expired Domains» политики на 301.st;
  - раскрытие данных в CWS и AMO.

## Риски

- **Политика Ahrefs уже менялась.** За два месяца бесплатный эндпоинт стал требовать ключ.
  Функция может перестать работать без предупреждения.
- **Ревью в магазинах.** Расширение «без сети» проходит проще. Из-за запросов к Ahrefs
  ревьюеры зададут вопросы, а описание в магазинах придётся поменять.
- **Если ключ доступен только на платном тарифе**, функция нужна немногим.
