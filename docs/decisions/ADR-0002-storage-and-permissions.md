# ADR-0002: Хранение по ключам на домен, `unlimitedStorage`, без `host_permissions`

Дата: 2026-11-19. Частично заменяет раздел «Последствия» в [ADR-0001](ADR-0001-mv3-capture-only.md)
(лимит ~10 МБ и один ключ). Детали — [SPEC](../SPEC.md): I4, Ф9–Ф12, раздел 6.

## Контекст
- Цель — до 10 000 доменов. Реальная запись с 27 колонками статистики (по фикстурам)
  занимает ~0,7 КБ, то есть ~7 МБ при квоте `storage.local` в Chrome 10 МБ.
- Набросок держит всё в одном ключе `eds:v1` и переписывает его целиком при каждом
  захвате, через дебаунс 300 мс. При остановке MV3 service worker данные теряются.
- Расширение идёт в магазины (CWS, Edge, AMO): каждое право нужно обосновать.

## Решение
1. **Хранение:**
   - одна запись `d:<домен>` на домен плюс `meta` и `settings`;
   - один писатель (background) и последовательная очередь мутаций;
   - ответ отправляется после записи;
   - частичная запись допустима. Мутация идёт в три шага с маркером `meta.pending`.
     При старте `ensureReady` обычно читает только `meta`, а полностью пересобирает её
     только после прерванной мутации. Worker засыпает через ~30 с, поэтому полное чтение
     при каждом старте стояло бы почти перед каждым захватом.
2. **`unlimitedStorage`** — запас над квотой. В Chrome и Edge предупреждения при установке
   нет; в Firefox возможная строка в окне установки допускается (SPEC М2, ADR-0003).
3. **Без `host_permissions`.** Доступ к сайту — только через `content_scripts.matches`.
   Явные host-права дали бы background и popup возможность делать запросы к сайту, а это
   противоречит capture-only.

## Альтернативы и почему нет
- **Один ключ без `unlimitedStorage`.** Близко к квоте, весь массив переписывается при
  каждом захвате.
- **IndexedDB с транзакциями.** Даёт атомарность, но добавляет сложность. Список
  пересобирается повторным захватом, поэтому строгая атомарность не нужна (ревью ТЗ,
  SPEC Ф11).
- **Журнал (write-ahead) поверх `storage.local`.** Та же причина.
- **Право `downloads` для экспорта в Firefox.** Не берётся, пока Blob-скачивание проходит
  A11. Если нет — новый ADR.

## Последствия
- Popup читает `get(null)` (~7 МБ на 10k) и перед этим ждёт `ensureReady`.
- Бейдж берётся из `meta.domainCount`, а не из полного пересчёта.
- Полный список прав: `storage`, `unlimitedStorage`, в Chrome/Edge ещё `sidePanel`
  (I4; `sidePanel` добавлен ADR-0003). Любое новое право — новый ADR.
