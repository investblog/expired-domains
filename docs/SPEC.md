# ТЗ: Expired Domains v1

Версия ТЗ: 0.7 (2026-11-20). От 0.6 отличается уточнениями, найденными при реализации и
ревью кода:
- разбор страницы: `adddate` есть на всех страницах с входом (Д2), правило `no_rows` /
  `no_domain_column` и повтор домена на странице (Е1), колонка `dropped` только при
  разобранной подсказке (Д8в);
- хранение: каждая мутация сама сверяет `pending`, `setSettings` одним `set` (Ф11);
  восстановление проверяется и в background (Ф27);
- экспорт: `last_source` — подпись, защита от формул пропускает C1 и невидимые символы (Ф17);
- фильтр: счётчик «нет данных», regex — не больше 2 квантификаторов переменной длины (Ф25);
- подборки: встроенный вид `all` «Без отклонённых» (до 2026-11-20 — «Все, кроме отклонённых»; сокращено, чтобы помещалось в боковую панель) по умолчанию, имена встроенных
  проверяет интерфейс (Ф13, Ф26); теги без `,` и `;` (Ф21);
- резервная копия: `status`/`tags`/`note` (Ф27);
- раздел 2: рантайм WXT в content script (`postMessage`, `dispatchEvent`), скрытности нет;
- стартовая страница при установке и новое пустое состояние — для тех, кто не знает сайт
  (Ф13б, Ф13);
- popup убран: иконка открывает боковую панель во всех браузерах (Ф13а, [ADR-0005](decisions/ADR-0005-sidepanel-only.md)); в ней
  формы — в выезжающих панелях, прокручивается только список, экспорт закреплён внизу
  (Ф13, Ф16а); иконка в цветах 301.st (М5);
- иконки интерфейса — спрайт из набора 301-ui, подвал — ряд иконок-ссылок со ссылкой на
  чат поддержки; хост панели на сайте без paint-containment (2026-11-21; Ф16а, Ф3).

Основа:
- набросок кода в корне репозитория (логика и находки; сам код заменяется проектом WXT);
- [ADR-0001](decisions/ADR-0001-mv3-capture-only.md),
  [ADR-0002](decisions/ADR-0002-storage-and-permissions.md),
  [ADR-0003](decisions/ADR-0003-wxt-and-301-conventions.md),
  [ADR-0004](decisions/ADR-0004-ahrefs-dr-opt-in.md),
  [ADR-0005](decisions/ADR-0005-sidepanel-only.md);
- образец стека и оформления — `redirect-inspector` и `agent-readiness` (раздел 8.2).

Где ТЗ расходится с наброском, прав ТЗ (сводка расхождений — раздел 11).

Пометка **[не проверено]** означает, что факт ещё не сверен с реальной страницей сайта или
документацией браузера. В релиз такие пункты не уходят.

## 1. Назначение и границы

Расширение браузера сохраняет домены из таблиц expireddomains.net, **которые пользователь
открыл сам**, копит их между страницами и выгружает в CSV, TXT или буфер обмена.

Входит в v1:
- распознавание таблицы доменов на открытой странице;
- ручное сохранение страницы и автосбор при загрузке страницы;
- накопление без дублей;
- просмотр, фильтр, экспорт и очистка в боковой панели;
- разбор накопления (раздел 4.6): статусы, теги вместо коллекций, заметки, фильтры
  «только рабочие» с предустановками, массовые действия, резервная копия JSON.

Не входит в v1 (бэклог — [TODO.md](TODO.md)):
- выбор колонок для CSV;
- сортировки;
- импорт CSV/TXT (восстановление из своей резервной копии JSON — входит);
- коллекции как отдельные хранилища: их заменяют теги (Ф21);
- переименование тегов;
- реакция на обновление таблицы без перезагрузки страницы (см. С2);
- проверка Ahrefs DR ключом пользователя — **v1.1**, включается по желанию и меняет
  I1/I4/I5 ([ADR-0004](decisions/ADR-0004-ahrefs-dr-opt-in.md)).

Целевой объём: **до 10 000 доменов** в одном накоплении (решение пользователя, 2026-11-19).
Распространение: Chrome Web Store, Edge Add-ons, AMO (решение пользователя, 2026-11-19).

## 2. Инвариант «capture-only» (проверяемый)

Это ядро продукта. Нарушение любого пункта считается блокирующим дефектом.

| # | Требование | Как проверяется |
|---|---|---|
| I1 | Расширение не делает сетевых запросов: нет `fetch`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`, `EventSource`, `importScripts`; нет `<img>`/`<script>`/`<iframe>`/CSS `url()` с внешними адресами | A1 (скан) + A8 (сеть в живом браузере) |
| I2 | Расширение не управляет сайтом: нет программных кликов, `dispatchEvent`, отправки форм, `focus()`/`scroll*` по элементам сайта, смены `location`, `history.*`, `window.open` | A1. Исключения: `a.click()` по собственной ссылке-скачиванию внутри боковой панели; `tabs.create` своей стартовой страницы — только background, один раз при установке (Ф13б) |
| I3 | Нет авто-пагинации и «следующей страницы». Автосбор только читает уже загруженную страницу | A1 + ревью |
| I4 | В каждом собранном манифесте (`dist/chrome-mv3`, `dist/edge-mv3`, `dist/firefox-mv2`): `permissions` — ровно `storage`, `unlimitedStorage` во всех трёх и в Chrome/Edge ещё `sidePanel` (матрица заморожена; в Chrome/Edge все три без предупреждения при установке, в Firefox возможная строка про `unlimitedStorage` в окне установки допускается — М2). Боковая панель: Chrome/Edge — `side_panel.default_path`, Firefox — `sidebar_action.default_panel`, обе на `sidepanel.html`; popup нет — у `action`/`browser_action` нет `default_popup`; в Firefox есть `commands._execute_sidebar_action` (Ф13а). **Нет** `host_permissions`, `optional_permissions`, `optional_host_permissions`, `web_accessible_resources`, права `tabs`. Доступ к сайту — только через `content_scripts.matches`: `*://expireddomains.net/*`, `*://*.expireddomains.net/*`. CSP по умолчанию | A2 |
| I5 | Данные не покидают браузер: нет аналитики, телеметрии, удалённого кода | A1 + A8 |
| I6 | Со страницы читаются только (а) содержимое `#listing` и (б) метаданные: `location.host` и `location.pathname`, параметр `q` у поиска (Д10), `document.title`, `.pageinfo` пейджера. Шапка сайта, имя аккаунта, email, баланс и прочее вне `#listing` не читаются и не сохраняются | A3 (фикстура с меткой-«ловушкой» вне `#listing`) |

Автосбор (I3) разрешён: это то же чтение DOM открытой страницы, только без нажатия кнопки.
Ответственность за темп просмотра лежит на пользователе (README).

Скрытности от сайта расширение не обещает: страница видит элемент панели в DOM и сообщение
`window.postMessage`, которое рантайм WXT отправляет при старте content script (так он
останавливает старую копию скрипта после обновления расширения). Ещё рантайм WXT вызывает
`dispatchEvent` своего события `wxt:locationchange` на `window`. Это не запросы и не
управление сайтом (I1, I2); в A1 оба места вносятся в список разрешённых поимённо.

## 3. Пользовательские сценарии

**С1. Ручной сбор.** Пользователь залогинен и открывает список (например, deleted domains).
Справа появляется панель «На странице: N доменов · стр. X из Y». Он жмёт «Сохранить
страницу» и видит «+K новых, обновлено M · всего T». Затем сам переходит на следующую
страницу и повторяет.

**С2. Автосбор.** Пользователь включает в панели «Автосбор». Каждая следующая страница
списка, которую он открывает сам, сохраняется после загрузки без нажатия, а панель
показывает результат.

Если сайт обновляет таблицу без перезагрузки страницы, v1 на это не реагирует: панель
показывает число, посчитанное при загрузке, а «Сохранить» перечитывает таблицу в момент
нажатия. Признаков AJAX на сайте не найдено (Д12): фильтр и сортировка перезагружают
страницу. Поддержка AJAX (MutationObserver) входит в объём, только если это изменится. Тогда для неё пишется отдельный контракт:
- область наблюдения — только `#listing`;
- дебаунс до стабилизации;
- изменения от собственной панели игнорируются;
- приёмка на фикстуре с мутацией DOM.

**С3. Выгрузка.** Пользователь открывает боковую панель (клик по иконке). Он видит общее число, разбивку по спискам,
фильтр и кнопки «Копировать / CSV / TXT / Очистить».

**С4. Вёрстка сайта изменилась.** На странице есть `#listing`, но таблица или колонка
домена не распознаны. Тогда панель явно об этом сообщает (раздел 7). Молча сохранить 0
доменов недопустимо. На странице без `#listing` панели нет совсем.

## 4. Функциональные требования

### 4.1 Панель на странице (content script)
- **Ф1.** Панель появляется только на страницах, где есть блок `#listing` (Д1). На
  остальных страницах сайта её нет; скрипт там только отвечает боковой панели, что списка
  на странице нет (Ф13в). Если `#listing` есть, но таблица или колонка
  домена не распознаны, панель показывается в режиме предупреждения (Е2).
- **Ф2.** Панель показывает:
  - число доменов на странице;
  - «стр. X из Y» (Д9);
  - кнопку «Сохранить страницу»;
  - переключатель «Автосбор»;
  - строку статуса;
  - кнопку «свернуть» (состояние запоминается).
- **Ф3. Панель.**
  - **Размещение:** фиксированная, в правом верхнем углу, ширина ≤ 240 px. В свёрнутом
    виде — значок ≤ 40×40 px. Полного «не перекрывает ничего» не обещаем: панель
    перекрывает минимум и сворачивается одним кликом. При ширине окна < 1000 px она по
    умолчанию свёрнута.
  - **Ф3а. Режим автосбора на свёрнутом значке** (просьба владельца 2026-11-21: иначе можно
    забыть, что автосбор включён). Пока сохранённая настройка `autoCapture` включена, значок
    залит основным цветом с белой иконкой (контраст 6,3:1 в светлой теме и 4,7:1 в тёмной), а
    его подсказка и `aria-label` говорят «автосбор включён». Значок меняется только после
    того, как переключатель сохранён (Ф11 «Отправитель»). Когда в режиме автосбора захват
    добавил **новые** домены (`added > 0`; при одних обновлениях — нет), проходит один блик
    (1,2 с): по значку, если панель свёрнута, по кнопке «Сохранить страницу», если развёрнута.
    Без автосбора ручное сохранение блика не даёт.
    При `prefers-reduced-motion: reduce` вместо движения — короткое затухающее свечение на
    месте.
  - **Изоляция:**
    - один хост-элемент с уникальным id;
    - closed Shadow DOM;
    - в корне `:host { all: initial }`, шрифт и размеры заданы явно;
    - `contain: layout style` — без `paint`: paint-containment обрезает тень кнопки и
      панели по рамке хоста (на сайте вокруг круглой кнопки был виден серый квадрат);
    - корень создаётся вручную (`attachShadow({ mode: 'closed' })`), а не через
      `createShadowRootUi` WXT. CSS панели — строка в бандле content script, она
      вставляется элементом `<style>` в shadow root (так делает `cloudflare-tools`).
      Никакой загрузки CSS по URL расширения и никаких `web_accessible_resources` (I4).
  - **Оформление** — токены 301.st (раздел 8.2), но с поправками для чужой страницы:
    - токены объявляются на `:host`, а не на `:root`;
    - размеры в `px`, не в `rem` (`rem` считается от корня сайта, а не от панели);
    - тема — только `prefers-color-scheme`. `localStorage` в content script — это
      хранилище сайта, панель его не использует.
    - Перед реализацией замерить, сколько из ~90 токенов реально нужно панели; в бандл
      идут только они.
  - **Приёмка:** визуальная проверка при ширине 1920, 1280 и 800 px (A8).
- **Ф4.** Повторное «Сохранить» на той же странице не создаёт дублей (Ф8).

### 4.2 Распознавание (парсер)
- **Ф5.** Парсер — чистая функция `parseListing(document) → { rows, columns, pager, diagnostics }`.
  Она не обращается к `location` и не знает об источнике, поэтому её можно тестировать вне
  браузера на HTML-фикстурах.
  Оркестратор в content script добавляет контекст страницы: `sourceId` и `sourceLabel`
  (Д10).
- **Ф6.** Таблица и колонки определяются строго по контракту раздела 5:
  - таблица — Д1;
  - колонки — по ключу класса `head_<key>`/`field_<key>` (Д2), а не по позиции и не по
    тексту;
  - значение ячейки — Д7;
  - UI-колонки пропускаются (Д3).
- **Ф7. Домен.**
  - **Источник:** `title` у первой ссылки в `td.field_domain` без класса `favicons` (Д4).
    Запасной — `/domain/<имя>` (Д5), на публичных страницах его нет. Текст
    ссылки как источник имени запрещён: он обрезается.
  - **Нормализация:**
    - обрезка пробелов;
    - нижний регистр;
    - удаление завершающей точки.
  - **Валидация:**
    - ≥ 2 меток;
    - общая длина ≤ 253;
    - метка 1–63 символа `[a-z0-9-]`, не начинается и не заканчивается дефисом;
    - punycode (`xn--`) принимается.
  - Строки с Unicode-IDN не конвертируются: они отбрасываются и учитываются в
    `diagnostics.rejected` (как сайт показывает IDN — Д6, **[не проверено]**).
- **Ф8. Ключ записи — домен.** При повторном захвате:
  - `firstSeen` не меняется;
  - `lastSeen`, `lastSource` и `stats` перезаписываются свежими значениями. `stats`
    заменяется **целиком** — это снимок строки последнего захвата. Колонки, которых в
    последнем списке не было, у домена пропадают. Так все относительные значения
    (`32 days`, `5h 33m`) всегда отсчитываются от одного момента — `lastSeen` (Ф24);
  - `sourceId` добавляется в множество `lists`, если его там ещё нет;
  - пользовательские поля `status`, `tags`, `note` (Ф20–Ф22) **не меняются никогда**.

  Домен, встреченный в двух списках, учитывается в разбивке обоих. Но снимок `stats` у
  него один — из `lastSource`, и **условия Ф25 по статистике проверяются по этому
  снимку**. Строка списка показывает, из какого списка снимок. Строка устроена как таблица
  доменов 301-ui: две колонки — имя (занимает остаток ширины) и колонка бейджей справа
  (не сдвигается и всегда на первой строке).
  - **Имя** — главное в строке: без многоточия, длинное переносится внутри своей колонки
    (`overflow-wrap: anywhere`). Имя полужирное, зона (всё после первой точки) приглушена.
  - **Колонка бейджей:** тип списка (удалён / к удалению / истёк / аукцион / продажа /
    наблюдение / поиск — по заголовку страницы списка; неизвестный тип без бейджа) и знак зоны
    без текста. Тип списка — колонка низкого приоритета: при ширине списка ≤ 340 px скрыт
    (container query). Полное название списка — во всплывающей подсказке строки и в карточке.
  - **Знак зоны** — флаг страны для национальной зоны (по последней части зоны: `.co.uk` → GB;
    `.eu`, `.ac`, IDN `.рф`/`.укр`/`.бел`/`.срб`/`.қаз`/`.мкд` — по таблице) или глобус для
    общей: gTLD, городские и региональные gTLD, национальные зоны из списка Google «generic
    ccTLD» (.ad .ai .as .bz .cc .cd .co .dj .fm .io .la .me .ms .nu .sc .sr .su .tv .tk .ws) и
    зоны без флага. Подсказка и `aria-label` — зона, название страны на языке интерфейса
    (`Intl.DisplayNames`) и/или «общая зона». Флаги — `flag-icons` (MIT), по файлу на страну
    в пакете, загружаются только нужные.
  - **Вторая строка** — только если есть что показать: статус Ф20 цветным значком (★ отобран,
    ✕ отклонён, ✓ куплен; «новый» без значка; название — в подсказке и `aria-label`), до двух
    тегов (длинный обрезается многоточием, полный — в подсказке; остальные — «+N» с полным
    списком в подсказке) и значок заметки.

  Пример ограничения: домен
  с аукциона GoDaddy, позже собранный со страницы Watchlist (там нет `endtime`), больше не
  проходит условие «аукцион ещё идёт» (Ф25), пока его снова не соберут со страницы
  аукциона. Снимки по каждому списку в v1 не хранятся.

### 4.3 Хранение (background)
- **Ф9. Единственный писатель.** В хранилище пишет только background. Content script и
  боковая панель работают через сообщения. Боковая панель читает хранилище напрямую, только на
  чтение.
- **Ф10. Очередь мутаций.**
  - Все изменения идут через одну последовательную очередь в background: `add`, `clear`,
    `delete` и `clearList` (Ф15а), `setSettings`, `update` (статус, теги, заметка у одного
    или многих доменов — Ф23), `restore` (Ф27).
  - Источник истины — `storage.local`, а не глобальные переменные. Каждая операция
    читает нужные ключи из хранилища внутри очереди.
  - Ответ отправителю уходит **после** того, как промис `storage.local.set`/`remove`
    выполнился успешно.
  - Таймеры-дебаунсы запрещены.
  - **Последний шаг любой мутации** записывает `meta` с `rev` на единицу больше. По
    этому изменению открытая боковая панель понимает, что пора перечитать
    данные (Ф16).
  - `add` безопасна для повтора: повтор того же захвата не плодит записи и не меняет
    `firstSeen`. `lastSeen` при этом может сдвинуться, а счётчики «новых/обновлено» в
    ответе — отличаться. Это допустимо.
- **Ф11. Ошибка записи и частичное состояние.** `storage.local` не транзакционно:
  многоключевой `set` не гарантирует «всё или ничего» при падении worker или браузера.
  - **Запись.** Каждая запись `d:*` самодостаточна (домен, даты, `lists`, `stats`).
    Частичная запись (часть доменов страницы сохранена, `meta` нет) допустима.
  - **`update` идёт без протокола `pending`:** он меняет записи `d:*` и в том же `set`
    только `meta.rev` (счётчики, `sources` и `columns` не меняются). Частично
    применённое массовое `update` оставляет каждую запись целой. Отправитель получает
    ошибку и может повторить: операция идемпотентна.
  - **Протокол многоключевой мутации** (`add`, `clear`, `delete`, `clearList`, `restore`) —
    три шага:
    1. `set({ meta: { …meta, pending: true } })` (у `restore` — с итоговыми
       справочниками, см. ниже);
    2. запись данных: `set` записей `d:*`; `remove` для `clear`; у `restore` — см. ниже;
    3. `set` новой `meta` без `pending`, с обновлёнными `domainCount`, `sources`,
       `columns`, `columnOrder`. Шаг 3 пишет **только** `meta`: всё остальное записано
       на шаге 2, поэтому снятый `pending` означает, что данные на месте.

    Если операция прервана между шагами, `meta.pending` остаётся `true`.
  - **Сверка `ensureReady` при старте worker.** Worker засыпает через ~30 с простоя,
    поэтому при ручном листании она идёт почти перед каждым захватом и обязана быть
    дешёвой:
    - **быстрый путь (обычный):** читаются только `meta` и `settings`;
    - **пустое хранилище** (нет ни `meta`, ни `d:*` — первый запуск) → записывается
      пустая `meta` (`domainCount: 0`, `rev: 0`) и `settings` по умолчанию;
    - **полная пересборка** — только если `meta.pending === true` или `meta` нет, а
      записи `d:*` есть. Тогда читаются все ключи и **`meta` пересобирается целиком** по
      записям `d:*` (`rev` увеличивается):
    - `schema = 2`;
    - `domainCount` = число `d:*`;
    - `sources`:
      - метки `sourceId`, на которые ссылаются записи, сохраняются;
      - метки без ссылок удаляются;
      - недостающие получают метку `= sourceId`;
    - `columns`: то же правило; недостающие колонки получают
      `{ label: key, title: "" }`;
    - `columnOrder`:
      - существующий порядок сохраняется для ключей, на которые есть ссылки;
      - недостающие ключи дописываются в конец, отсортированные по коду символов.

    Следующий захват заменяет запасные метки настоящими (`label`/`title` из `th`).
  - **Порядок.** Слушатели `runtime.onMessage` регистрируются синхронно в `main()`
    background-точки входа WXT (`src/entrypoints/background.ts`). `ensureReady` — первая задача в очереди мутаций (Ф10). Каждая
    мутация ждёт её завершения, поэтому устаревшая сверка не может перезаписать более
    свежую `meta`.
  - Если мутация в том же запуске worker упала посреди протокола, `meta.pending` остаётся.
    Поэтому каждая мутация, увидев `pending` или отсутствие `meta`, сначала выполняет
    сверку и только потом свою работу.
  - `setSettings` пишет `settings` и `meta.rev` одним `set`, как `update`.
  - **Боковая панель** перед чтением хранилища отправляет `eds:ensureReady` и ждёт ответа.
    Так она не покажет несверенное состояние.
  - **Отправитель.** Ошибкой считается и ответ `{ error }`, и отклонённый или закрытый
    канал `runtime.sendMessage` (worker остановлен до ответа). Оба случая панель
    показывает одинаково: «Не сохранено — повторите». Захват можно повторить.
  - **`clear`** идёт по тому же протоколу. Шаг 2 — `remove` всех `d:*`, шаг 3 — пустая
    `meta` с новым `rev` (ключ `meta` не удаляется: по нему обновляются открытые списки,
    Ф16).
  - **`delete` и `clearList`** (Ф15а) идут по тому же протоколу. Шаг 2 — `remove` удаляемых
    `d:*` и `set` изменённых (у `clearList`); шаг 3 — `meta`, пересобранная по оставшимся
    записям по правилам сверки ниже (`rev` + 1, метки и колонки без ссылок убираются).
    Прерванная операция оставляет `pending`, сверка при старте приводит `meta` к записям;
    повтор доводит до того же итога.
  - **`restore`** на шаге 1 пишет `pending: true` **вместе с итоговыми** `sources`,
    `columns`, `columnOrder` (Ф27). Если восстановление прервётся, пересборка `meta`
    сохранит эти подписи и порядок для всех ключей, на которые ссылаются записи, и
    повтор восстановления не получит вместо них запасные.
    - Шаг 2 «Объединить»: `set` итоговых записей и `settings`.
    - Шаг 2 «Заменить всё»: `remove` записей `d:*`, которых нет в копии; затем `set` всех
      записей копии и `settings`. Совпадающие домены не удаляются, а перезаписываются. Прерванная очистка оставляет `pending`, и при старте `meta` пересобирается
    по остатку.
- **Ф12.** Бейдж на иконке показывает общее число доменов (`1.2k` от 1000). Источник —
  `meta.domainCount`. Он обновляется на шаге 3 мутации и пересобирается только по Ф11.
  Полного чтения всех `d:*` в обычном захвате нет.

### 4.4 Боковая панель
- **Ф13а. Боковая панель — единственная страница расширения, popup нет** (стандарт
  расширений 301.st, решения пользователя 2026-11-19 и 2026-11-20, [ADR-0005](decisions/ADR-0005-sidepanel-only.md)). Точка входа
  WXT `sidepanel` — страница `sidepanel.html`; по ней WXT строит `side_panel` (Chrome/Edge) и
  `sidebar_action` (Firefox):
  - **Chrome / Edge:** клик по иконке открывает боковую панель
    (`sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` в background, при каждом
    запуске worker); у `action` нет `default_popup`;
  - **Firefox:** у `browser_action` нет `default_popup`; клик по иконке вызывает
    `browserAction.onClicked` → `sidebarAction.open()` прямо в обработчике (нужен жест
    пользователя). Боковая панель доступна и из меню «Вид → Боковые панели», и сочетанием
    клавиш (`commands._execute_sidebar_action`).

  Зачем это здесь: панель остаётся открытой, пока пользователь листает страницы сайта, а
  список обновляется сам (Ф16). Видно, как растёт накопление.

  Боковая панель **не заменяет** панель на странице (Ф1–Ф3). Число доменов на текущей
  странице и кнопка «Сохранить» остаются на странице. Боковая панель обращается к вкладке
  только в пустом состоянии и только через наш content script (Ф13в); саму страницу она не
  читает.
- **Ф13в. Живые шаги в пустом состоянии** (0.1.2, жалоба первых пользователей 2026-11-23:
  «зашёл с логином и паролем — только боковая панель и всё»; решение пользователя: живая
  подсказка с кнопкой сохранения, на страницах сайта без списка ничего не показывать).
  - **Как узнаёт вкладку:** `tabs.query({ active: true, currentWindow: true })` даёт id
    активной вкладки (без разрешения `tabs`), `tabs.sendMessage(id, { type: 'edsTab:state' })`
    — ответ нашего content script. Адрес вкладки расширению не виден: проверено 2026-11-23 в
    Chromium — `matches` content script не дают `tab.url`. Новых разрешений нет (A2).
  - **Ответ скрипта:** `{ listing: false }` на страницах сайта без `#listing`; на странице
    списка `{ listing: true, mode: 'ready' | 'empty' | 'broken', rows }` — по тому же разбору,
    что и панель на странице (Е2). Нет ответа — сайт не открыт, или вкладка открыта до
    установки (скрипта там нет, пока страницу не обновят).
  - **Шаги:** (1) «Откройте ExpiredDomains.net и войдите» — ссылки «Открыть
    ExpiredDomains.net», «Зарегистрироваться бесплатно» и подсказка «Сайт уже открыт?
    Обновите вкладку»; (2) «Откройте список доменов» — кнопка «Удалённые домены .com»
    (`https://member.expireddomains.net/domains/expiredcom/`, обычная ссылка) и «или любой
    список из меню сайта»; (3) «Сохраните страницу» — число доменов на странице, кнопка
    «Сохранить эту страницу», флажок автосбора (та же настройка, что на странице; панель
    на странице следит за её изменением). Пройденные шаги — с галочкой, текущий раскрыт.
  - **«Сохранить эту страницу»** шлёт вкладке `edsTab:save`; скрипт идёт тем же путём, что
    кнопка на странице (повторный разбор в момент сохранения, защита от двойного нажатия,
    `eds:add` в background, Ф9). Итог — во всплывающем сообщении; после первого сохранения
    пустое состояние сменяется списком.
  - **Когда спрашивает заново:** `tabs.onActivated`, `tabs.onUpdated` (смена статуса) и
    сообщение `edsTab:ready`, которое скрипт шлёт, когда страница готова (`document_idle`
    может наступить позже `complete`).
  - Сообщения `edsTab:*` не входят в протокол записи (`eds:*`, Ф11): background их не
    обрабатывает, слушатели отвечают только на свои типы.
  - Без API вкладок (стенд скриншотов, ролик) шаги показываются как при закрытом сайте.
- **Ф13б. Стартовая страница** `welcome.html` (как в остальных расширениях 301.st, решение
  пользователя 2026-11-20). Человек, не знакомый с сайтом, должен понять, что это за сайт,
  зачем расширение и что нужен аккаунт:
  - **когда:** background открывает её один раз — `runtime.onInstalled` с
    `reason: 'install'` → `tabs.create` своей страницы. Флага в хранилище нет (раздел 6).
    При обновлении не открывается. Ссылка «Как это работает» есть в подвале боковой панели
    и в пустом состоянии. В Firefox боковая панель при установке сама не открывается
    (`sidebar_action.open_at_install: false`);
  - **порядок:** что такое ExpiredDomains.net (бесплатный сервис со списками освобождающихся
    доменов) → зачем расширение → шаги: (1) войти на сайт — большинство списков видно только после входа
    (2026-11-20, снимок пользователя: публичная «Deleted .com Domains» без входа показывает
    только «Login to see all Domains», таблицы нет; фикстура без входа снята раньше),
    хватит бесплатного аккаунта; ссылки «Зарегистрироваться бесплатно»
    `https://www.expireddomains.net/register/` и «Открыть ExpiredDomains.net»
    `https://www.expireddomains.net/`; (2) открыть список; (3) «Сохранить страницу» или
    автосбор; (4) разобрать список в боковой панели → что есть в боковой панели, кнопка
    «Открыть боковую панель» (`sidePanel.open` / `sidebarAction.open` по клику) →
    приватность, «Неофициальное…» (М5), ссылки «Оценить», GitHub, 301.st;
  - страница не делает запросов (I1); ссылки — обычные `<a target="_blank">` (Ф16а).
- **Ф13.** Боковая панель показывает:
  - общее число доменов («N из M» над списком и у кнопок выгрузки);
  - разбивку по спискам (подписи из `meta.sources`, членство из `lists`) — чипы со
    счётчиками в группе «Списки» панели фильтров;
  - поле фильтра: подстрока, или regex в виде `/…/`; неверный regex подсвечивается и
    не применяется. Это условие `text` фильтра Ф25 (там же ограничения regex);
  - панель фильтров и выбор предустановки (Ф25, Ф26);
  - список (до 500 строк, остальное — счётчиком). В строке: домен, статус, теги, значок
    заметки, флажок выбора (Ф23). Клик по строке открывает редактор статуса, тегов и
    заметки.

  **Раскладка** (решение пользователя 2026-11-20, как в остальных расширениях 301.st):
  прокручивается только список. Над ним — строка поиска, выбор предустановки, кнопка
  «Фильтры» со счётчиком действующих условий и чипы статусов; под ним закреплены
  «Копировать», «CSV», «TXT». Формы над списком не стоят — они открываются в выезжающей
  справа панели (drawer, образец 301-ui): условия фильтра и управление предустановками;
  редактор строки (сохраняет и закрывается; там же «Удалить», Ф15а); массовые действия (Ф23,
  кнопка «Изменить…» над выбранными; там же «Удалить выбранные», Ф15а); «Данные и резервная
  копия» из шапки — удаление тегов (Ф21), резервная копия и восстановление (Ф27), очистка
  одного списка (Ф15а) и всех доменов (Ф15). Условия применяются сразу и остаются в силе после
  закрытия панели. Escape и клик по затемнению закрывают её, фокус возвращается.

  **Вид по умолчанию** — все домены, кроме отклонённых (Ф20): встроенный вид `all` (Ф26).

  **Пустое состояние** — короткая версия Ф13б: что собирает расширение и с какого сайта,
  три живых шага по активной вкладке (Ф13в), ниже — «Как это работает» и «Восстановить из
  резервной копии…».
- **Ф14.** «Копировать», «CSV» и «TXT» работают с **текущей выборкой** — результатом всех
  условий фильтра вместе (Ф25), а не с 500 показанными строками. Рядом показано «N из M».
- **Ф15.** «Очистить» удаляет все записи `d:*` и заменяет `meta` пустой (`domainCount: 0`,
  `rev` на единицу больше, Ф11) после подтверждения внутри боковой панели (вторая
  кнопка «Да, удалить N»). Настройки и предустановки сохраняются.
  - В подтверждении сказано, что статусы, теги и заметки тоже удалятся.
  - Там же есть кнопка «Сначала сохранить резервную копию» (Ф27).
- **Ф15а. Частичное удаление и очистка одного списка** (решение пользователя 2026-11-21).
  `rejected` по-прежнему только скрывает (Ф20); удаление стирает запись совсем, и домен,
  собранный снова, возвращается как новый. Подтверждение — как в Ф15, внутри панели: вопрос,
  предупреждение (статусы, теги и заметки удалятся; домен вернётся при новом сборе; чтобы
  только скрыть — «отклонён»), кнопка «Да, удалить N», «Сначала сохранить резервную копию»,
  «Отмена».
  - **«Удалить выбранные (N)»** в массовых действиях (Ф23) — выбранные домены, включая
    выбранные «Выбрать все N» за пределами 500 показанных. После удаления выбор снимается.
  - **«Удалить»** в карточке домена; карточка закрывается.
  - **«Данные и резервная копия» → «Списки»** — каждый список сайта из `lists` записей с
    числом доменов и кнопкой «Очистить». Домены, встреченные только в этом списке,
    удаляются; домен, собранный и с других списков, остаётся вместе со статусом, тегами и
    заметкой, а этот список убирается из его `lists`. Если снимок `stats` был с этого
    списка, снимок остаётся, а `lastSource` становится последним из оставшихся списков
    (`lastSource ∈ lists`, Ф7). Поэтому колонки этого снимка (и «список» в CSV) могут
    относиться к очищенному списку — принято: BL, DP и архив — свойства домена, а не списка;
    колонки аукциона и так устаревают, а снимок обновится при следующем сборе (ревью 2026-11-21). В подтверждении сказано,
    сколько удалится и сколько останется. Если за время вопроса число изменилось (автосбор в
    другой вкладке), «Да» не удаляет, а задаёт вопрос заново с новыми числами; то же у
    «Очистить всё» (Ф15).
- **Ф16.** Боковая панель обновляется сама, если открыта во время сбора:
  - из `storage.onChanged` берётся только изменение ключа `meta`. Изменения `d:*` и
    `meta` с `pending: true` пропускаются — мутация ещё не закончена;
  - перечитывание (`get(null)`) запускается по итоговой `meta` с новым `rev`. Пока оно
    идёт, новые изменения не запускают второе параллельное: после окончания выполняется
    ещё одно, если `rev` успел вырасти;
  - так один захват даёт одно перечитывание, а не три.
- **Ф16а. Оформление боковой панели** — как в остальных расширениях 301.st (раздел 8.2):
  - **шапка:** логотип 301.st (inline SVG, ссылка на `https://301.st/?utm_source=…`),
    название, кнопка «Данные и резервная копия» (Ф13), кнопка темы
    (переключает светлую ↔ тёмную; выбор — в `localStorage` страницы расширения под
    ключом `expired_domains_theme`). Пока пользователь не выбрал (ключа нет или старое
    значение `system`), тема следует за системой и ничего не пишется. Клик переключает от
    темы на экране и записывает выбор — следующие открытия уже с ним. (Раньше первый клик
    менял «системная → светлая», и при светлой системе на экране ничего не происходило.)
    Вернуться к «как в системе» после выбора нельзя — осознанно, как в cloudflare-tools.
    Если localStorage недоступен, выбор держится в памяти страницы до её закрытия;
  - **подвал** — ряд иконок-ссылок, как в остальных расширениях 301.st (подпись — в
    `title` и `aria-label`): «Как это работает» (стартовая страница, Ф13б) | «Оценить» —
    значок магазина текущего браузера, ссылка на страницу расширения в нём; GitHub —
    issues репозитория `investblog/expired-domains` | 301.st; чат поддержки в Telegram
    (`https://t.me/traffic301`);
  - все ссылки (и на стартовой странице, Ф13б) — обычные `<a target="_blank" rel="noopener">`,
    без `window.open` и `tabs.create` (I2);
  - иконки интерфейса — набор 301-ui: спрайты `src/assets/icons/mono.svg` (одноцветные,
    `currentColor`) и `brand.svg` (301.st, магазины, GitHub, Telegram). На страницах
    расширения спрайт один раз вставляется в документ, иконка — `<svg><use href="#i-…">`.
    Спрайт разбирается `DOMParser` и собирается `createElementNS`, не через HTML (I5).
    Панель на сайте не видит спрайт документа из closed shadow root, поэтому берёт копию
    нужного `<symbol>` (только mono, бренды в content script не попадают).

### 4.5 Экспорт
- **Ф17. CSV.**
  - **Формат:**
    - UTF-8 с BOM, разделитель `,`, перевод строки CRLF;
    - поля с `"`, `,`, CR или LF берутся в кавычки, `"` удваивается (RFC 4180).
  - **Порядок строк:** по возрастанию домена, сравнение по кодам символов (обычное `<`,
    не `localeCompare`). Тот же порядок в TXT (Ф18) и в списке боковой панели.
  - **Колонки:**
    - сначала `domain, status, tags, note, lists, last_source, first_seen, last_seen`.
      `tags` и `lists` (подписи) перечисляются через `; `; `last_source` — тоже подпись.
      Если подписи нет, выводится `sourceId`. `status` — код (`new`,
      `shortlist`, `rejected`, `bought`), а не перевод;
    - затем все колонки статистики, которые встречаются в выборке, в порядке
      `meta.columnOrder` (порядок первого появления; в наброске их режет до 12 — это
      потеря данных).
  - **Заголовки колонок статистики:**
    - `label` из `meta.columns` (`BL`, `DP`…);
    - если `label` пуст — `key`;
    - если один `label` у нескольких колонок (два «Status») — **у всех** таких колонок
      `label (key)`.
  - **Пустые и служебные значения:**
    - домен из списка без какой-то колонки получает пустую ячейку;
    - даты — ISO 8601 UTC.
  - **Заголовки и значения не локализуются.** Служебные колонки (`domain`, `lists`…)
    одинаковы в любом языке интерфейса, иначе файлы из разных браузеров не совпадут (A11).
  - **Защита от CSV-инъекции.**
    - Значение не изменяется. Ведущие пробелы, управляющие символы (C0, DEL, C1) и
      невидимые символы формата (U+200B–U+200D, U+2060, BOM) пропускаются только для поиска
      первого значимого символа.
    - Если этот символ — `=`, `+`, `-` или `@`, к **исходному** значению спереди
      добавляется `'`.
    - Исключение одно: значение ровно `-` (на сайте это «нет данных»).
  - **Excel.** Через «Данные → Из текста/CSV» файл открывается корректно в любой локали.
    Двойным кликом корректно открывается только в локали с разделителем списка `,`. Это
    осознанный компромисс в пользу RFC 4180, он описан в README.
  - Поле `note` может содержать `"`, `,` и переводы строк: правила RFC 4180 и защита от
    инъекций (выше) применяются к нему так же.
- **Ф18. TXT:** один домен на строку, LF, порядок как в Ф17.
- **Ф19. Имя файла:** `expired-domains-YYYY-MM-DD.csv|txt`, дата по **локальному**
  времени пользователя. Резервная копия — `expired-domains-backup-YYYY-MM-DD.json`.

### 4.6 Разбор накопления

Решение пользователя (2026-11-20) по исследованию
[collections.md](research/collections.md). Ни у одного конкурента нет рабочего процесса
«собрать → отсеять → отобрать → выгрузить отобранное». Здесь он есть, и всё работает
локально. Все пользовательские поля меняются только через `update` (Ф10). Захват их не
трогает (Ф8).

- **Ф20. Статус домена** — одно из четырёх значений: `new` («новый», по умолчанию),
  `shortlist` («отобран»), `rejected` («отклонён»), `bought` («куплен»).
  - Нет поля — значит `new`.
  - `rejected` — это «скрыть», а не «удалить». Такой домен не показывается в виде по
    умолчанию (Ф13). Если он снова попадётся при сборе, то останется отклонённым.
  - **Своей отметки в строках таблицы сайта нет** (решение 2026-11-20). На сайте уже есть
    «★ Watchlist» и «Dislike». Отмеченное звёздочкой собирается со страницы
    `/domains/watchlist/` как обычный список (Д10), а в расширении это фильтр «список =
    Watchlist Domains» (Ф25). Статусы расширения нужны для массового разбора всего
    накопленного и экспорта; статуса «куплен» на сайте нет.
- **Ф21. Теги вместо коллекций.**
  - У домена может быть **0–20 тегов**. Одна запись на домен сохраняется, поэтому дублей
    и копирования между коллекциями нет.
  - Нормализация имени тега:
    - обрезка пробелов, повторные пробелы схлопываются;
    - длина 1–40 символов (кодовых точек);
    - без `,` и `;`: запятая разделяет теги при вводе, точка с запятой — в колонке `tags` CSV
      (Ф17); иначе тег не пережил бы раунд-трип (находка ревью кода);
    - сравнение без учёта регистра;
    - хранится написание первого ввода.
  - Список тегов со счётчиками боковая панель считает сама по записям: он и так читает всё (раздел
    6). В `meta` теги не хранятся.
  - Тег исчезает, когда у него не осталось доменов.
  - «Удалить тег» — массовое `update`: тег снимается со всех доменов.
  - «Коллекция» для пользователя — это фильтр по тегу плюс экспорт (Ф14).
- **Ф22. Заметка** — свободный текст до 1000 символов. В списке показывается значком, а
  целиком — в редакторе строки.
- **Ф23. Массовые действия.**
  - У строк есть флажки выбора и кнопка «Выбрать все N в выборке». Она выбирает всю
    выборку фильтра, включая строки за пределами 500 показанных.
  - Над выбранными доступны три действия: поставить статус, добавить тег, снять тег.
  - Всё выполняется одним сообщением `eds:update { domains, patch }` (Ф10):

    ```ts
    type Patch = {
      status?: Status;       // 'new' удаляет поле status
      note?: string;         // '' удаляет поле note; ≤ 1000 символов
      addTags?: string[];    // добавляются без дублей (без учёта регистра), пока у домена не 20
      removeTags?: string[]; // снимаются без учёта регистра; пустой tags удаляет поле
    };
    ```

    Повтор того же `patch` даёт тот же результат. В ответе — число изменённых доменов и
    число доменов, где теги не поместились в 20. Домены, которых нет в хранилище,
    пропускаются.
- **Ф24. Время из относительных значений.** Сайт пишет часть времени относительно
  момента показа: `32 days`, `Yesterday 13:59`, `5h 33m`, `1d 11h 50m` (Д8). Снимок `stats`
  всегда относится к `lastSeen` (Ф8). Поэтому абсолютное время считается при показе и
  фильтрации, от `lastSeen`. В хранилище ничего лишнего не пишется.
  - **Форматы:**
    - `N day(s)`;
    - `Nd Nh Nm` с любыми опущенными частями;
    - `Today HH:MM`, `Yesterday HH:MM`;
    - дата `YYYY-MM-DD`.

    Всё остальное — «неизвестно».
  - **Направление по колонке:**
    - `changes` («Dropped») — в прошлое: дата освобождения;
    - `endtime` — в будущее: конец аукциона;
    - `enddate` — абсолютная дата удаления в pending delete;
    - `changetimer` — в прошлое. Подсказка ячейки на аукционе GoDaddy: `Changed 1 day,
      11 hours, 50 minutes ago` при значении `1d 11h 50m`. Это время с последнего
      изменения лота, а не конец аукциона, поэтому в Ф25 колонка не используется.
  - **Точность — сутки.** В каком часовом поясе сайт пишет `Yesterday 13:59`,
    **[не проверено]**. Расчёт идёт в локальном поясе пользователя, а в интерфейсе
    оценка помечена «≈».
  - Разбор — чистая функция `parseRelativeTime(text, kind, capturedAt)`. Она
    тестируется на таблице примеров из фикстур (A13).
- **Ф25. Фильтр** — набор условий через «И». Условия:

  | Условие | Данные | Если данных нет |
  |---|---|---|
  | Текст: подстрока или `/regex/` | имя домена | — |
  | Статус ∈ набор | `status` | считается `new` |
  | Тег: есть любой из / нет ни одного из | `tags` | тегов нет |
  | Список-источник ∈ набор | `lists` | — |
  | Свободен / занят | `whois` или `whois2`: `available` / `registered` (без учёта регистра) | не проходит |
  | Данные свежие: `lastSeen` не старше N часов | `lastSeen` | — |
  | Освободился не раньше N дней назад | `changes` → Ф24; если `changes` нет — `dropped` (Д8в) | не проходит |
  | Удаляется в ближайшие N дней | `enddate` → Ф24 | не проходит |
  | Аукцион ещё идёт | `endtime` → Ф24, конец позже текущего момента | не проходит |
  | Порог числа: BL ≥, DP ≥, записей в архиве ≥ | `bl`, `domainpop`, `aentries`; `93.2 K` → 93200, `6.8 M` → 6800000, запятые убираются | не проходит |
  | Возраст по архиву: первая запись не позже года Y | `abirth` | не проходит |
  | Имя: длина ≤ N, зона ∈ набор, без цифр, без дефисов | имя домена | — |

  - «Не проходит» означает, что домены без нужной колонки исключаются. Рядом с фильтром
    показывается, сколько доменов исключено по этой причине: в счётчик идут домены, которые
    не провалили ни одного условия по настоящим данным, но где-то упёрлись в отсутствие
    данных. Колонка есть, но значение не разобрано (`-`, мусор) — то же, что колонки нет.
  - Пересчёт выборки на 10 000 доменов укладывается в Н2.
  - **Тип фильтра** — один и тот же в интерфейсе, предустановках (Ф26) и резервной копии
    (Ф27). Отсутствующее поле — условие не применяется:

    ```ts
    type Status = 'new' | 'shortlist' | 'rejected' | 'bought';
    type Filter = {
      text?: string;              // подстрока или /regex/
      statuses?: Status[];        // статус ∈ набор
      tagsAny?: string[];         // есть хотя бы один из
      tagsNone?: string[];        // нет ни одного из
      lists?: string[];           // sourceId ∈ lists записи (хотя бы один)
      availability?: 'available' | 'registered';
      freshHours?: number;        // целые ≥ 1
      droppedWithinDays?: number; // целые ≥ 0
      deletesWithinDays?: number; // целые ≥ 0
      auctionActive?: true;
      minBl?: number; minDp?: number; minArchiveEntries?: number; // целые ≥ 0
      archiveFirstYearMax?: number;                               // 1990–2100
      maxNameLength?: number;     // 1–63
      zones?: string[];           // без ведущей точки: "com", "co.uk"
      noDigits?: true; noHyphens?: true;
    };
    ```
  - **Массивы** в `Filter` — непустые, без повторов (теги — без учёта регистра); пустой
    массив не сохраняется, условие тогда просто отсутствует. Зоны — в нижнем регистре,
    без ведущей точки, сравнение с доменом — тоже в нижнем регистре.
  - **Точный смысл условий.** «Сегодня» и границы дней — в локальном поясе пользователя;
    все границы включительны.
    - `text`:
      - без `/…/` — подстрока без учёта регистра;
      - `/…/` — тело regex, флаг всегда `i`, свои флаги не принимаются.
      - Тело regex — ограниченная грамматика от зависания: не длиннее 100 символов, не
        больше 5 квантификаторов (`* + ? {}`), из них не больше 2 переменной длины (`*`, `+`,
        `{n,}`, `{n,m}` при m > n: несколько подряд дают перебор порядка nᵏ — находка ревью
        кода), без квантификатора после группы (`(…)+`,
        `(a|aa)+`, `(…){2,}`), без обратных ссылок `\1`–`\9` и без lookaround
        (`(?=`, `(?!`, `(?<=`, `(?<!`). Неверный или отклонённый regex подсвечивается и
        не применяется. Это снижает риск, но не доказывает отсутствие зависаний (Н2).
    - **Имя** (`maxNameLength`, `noDigits`, `noHyphens`) — первая метка домена (до
      первой точки), как колонка сайта LE. **Зона** — всё после первой точки:
      `foo.co.uk` → `co.uk`.
    - `availability` — значение `whois`, а если его нет — `whois2`, без регистра и
      пробелов по краям. Проходит только точное совпадение. Прочие значения
      (`refused` и т. п.) не проходят ни как «свободен», ни как «занят».
    - `freshHours` — `lastSeen ≥ now − N ч`.
    - `droppedWithinDays` — дата освобождения (Ф24) не раньше начала дня `сегодня − N`.
    - `deletesWithinDays` — дата удаления от начала сегодняшнего дня до конца дня
      `сегодня + N`. Прошедшая дата не проходит.
    - `auctionActive` — есть `endtime` и конец по Ф24 позже `now`. Ключа `endtime` нет
      или конец не разобран — не проходит, как и остальные условия.
    - Пороги — число по правилу из таблицы `≥ N`; `archiveFirstYearMax` — первые четыре
      цифры `abirth` `≤ Y`.
- **Ф26. Предустановки.**
  - **Две встроенные** (решение пользователя 2026-11-20). На страницах аукционов колонки
    `whois` нет, поэтому одна общая подборка «свободен + аукцион идёт» не пропускала бы
    лоты вовсе:
    - `working-drops` «Рабочие — дропы»: свободен, данные не старше 24 ч, статус не
      `rejected` и не `bought` — `{ availability: 'available', freshHours: 24, statuses:
      ['new', 'shortlist'] }`;
    - `working-auctions` «Рабочие — аукционы»: аукцион идёт, данные не старше 24 ч,
      статус не `rejected` и не `bought` — `{ auctionActive: true, freshHours: 24,
      statuses: ['new', 'shortlist'] }`.

    Их нельзя удалить или изменить; можно сохранить копию под своим именем.
  - **Свои предустановки.** «Сохранить фильтр как…» записывает текущий набор условий в
    `settings.filterPresets`. Их можно переименовать и удалить.
    - Формат: `{ id, name, filter: Filter }`. `id` — `[a-z0-9-]{1,40}`, создаётся
      расширением; `id` с префиксом `working-` зарезервированы за встроенными.
    - Не больше 20; имя 1–40 символов, уникально без учёта регистра (и не совпадает с
      именами встроенных). Совпадение с именами встроенных (они зависят от языка) проверяет
      интерфейс при создании и переименовании; проверка резервной копии его не проверяет.
  - Активная предустановка запоминается (`settings.activePreset`: `id` встроенной или
    своей). По умолчанию и после удаления активной — вид `all` «Без отклонённых» (до 2026-11-20 — «Все, кроме отклонённых»; сокращено, чтобы помещалось в боковую панель)
    (Ф13): `{ statuses: [new, shortlist, bought] }`. Это не третья «рабочая» подборка, а
    исходный вид списка; его нельзя удалить или изменить, `id` `all` зарезервирован, как
    `working-*`. Без него Ф13 и Ф26 противоречили: пользователь, собравший только
    аукционы, при первом открытии видел бы пустой список «Рабочие — дропы» (решение
    2026-11-20 при реализации).
- **Ф27. Резервная копия и восстановление.**
  - **«Резервная копия»** скачивает JSON тем же способом, что CSV (раздел 8, A11):

    ```ts
    type Backup = {
      format: 'expired-domains-backup';
      version: 1;
      exportedAt: string;                    // ISO 8601 UTC
      records: Record<string, DomainRecord>; // ключ — домен в форме Ф7; значение — запись d:* без префикса (раздел 6)
      sources: Record<string, string>;       // sourceId → sourceLabel
      columns: Record<string, { label: string; title: string }>;
      columnOrder: string[];
      settings: Settings;                    // раздел 6; filterPresets — Ф26
    };
    ```
  - **Каноничная запись JSON:** ключи всех объектов отсортированы по кодам символов,
    отступ 2 пробела, LF, перевод строки в конце, UTF-8 без BOM. Одинаковые данные при
    одинаковом `exportedAt` (фиксированные часы в тесте) дают побайтно одинаковый файл
    (A11, A15).
  - В копию не входят служебные `meta.rev`, `meta.pending`, `meta.domainCount`.
  - **«Восстановить»** — в панели «Данные и резервная копия» боковой панели (Ф13); при
    пустом списке туда ведёт кнопка в пустом состоянии. Popup нет (Ф13а), поэтому вопрос
    «popup Firefox закрывается при выборе файла» снят.
    - Файл выбирается через `<input type="file">`, на который пользователь кликает сам
      через `<label>`: программного клика нет (I2). Читается `FileReader`, сети нет (I1).
  - **Проверка файла до записи.** Файл отклоняется целиком, если нарушено хоть одно:
    - размер ≤ 50 МБ; верхние ключи — ровно перечисленные в `Backup`; `format` и
      `version` совпадают; `exportedAt` — строка, для которой
      `new Date(s).toISOString() === s` (реальная дата в UTC, как её пишет экспорт);
    - ключи словарей (`records`, `sources`, `columns`, `stats`) не `__proto__`,
      `constructor`, `prototype`; при разборе и слиянии словари — `Map` или
      `Object.create(null)`;
    - `sources` и `columns` — по общим пределам раздела 6; `columns`: значение ровно
      `{ label, title }`;
    - ключ `records` уже в форме Ф7 (нормализация ключа ничего не меняет). Ключи не
      исправляются: иначе два ключа могли бы слиться в один;
    - запись: `firstSeen` и `lastSeen` — целые > 0, `firstSeen ≤ lastSeen`; `lists` —
      непустой массив без повторов, каждый элемент есть в `sources`; `lastSource ∈ lists`;
      `stats` — строка → строка по общим пределам раздела 6, ключи есть в `columns`;
      `status`, `tags`, `note` — по Ф20–Ф22 (`status` — только `shortlist`, `rejected`,
      `bought`: `new` не хранится; `tags` и `note` не пустые: пустые удаляют поле, Ф23);
      других полей нет;
    - `columnOrder` содержит каждый ключ `columns` ровно один раз и ничего больше;
    - `settings` — известные поля нужных типов; предустановки по Ф26, фильтры — по типу
      `Filter` (Ф25), неизвестные поля фильтра отклоняются; `activePreset` — `id` встроенной
      или `id` из копии.

    При любой ошибке ничего не записывается, а пользователь видит причину. Боковая панель
    проверяет файл для сообщения об ошибке, а в background уходит его текст
    (`eds:restore { text, mode }`), и background проверяет его ещё раз перед записью.
  - **Режимы.** «Заменить всё» — после подтверждения, как в Ф15: все записи, `sources`,
    `columns`, `columnOrder` и `settings` берутся из копии. **«Объединить»** (по
    умолчанию):

    | Что | Правило |
    |---|---|
    | Домен только с одной стороны | берётся как есть |
    | `firstSeen` | минимальное |
    | `lastSeen`, `lastSource`, `stats` | из записи с большим `lastSeen`; при равенстве — локальные |
    | `lists` | объединение: сначала локальные, затем новые из копии |
    | `tags` | объединение без учёта регистра: сначала локальные, затем из копии, пока не 20; число доменов, где теги не поместились, показывается в итоге |
    | `status` | локальный, если он есть и не `new`, иначе из копии |
    | `note` | локальная, если не пустая, иначе из копии |
    | `sources`, `columns` | объединение; при совпадении ключа — локальное значение |
    | `columnOrder` | локальный порядок, затем ключи, которых нет локально, в порядке копии |
    | `autoCapture`, `panelCollapsed`, `activePreset`, `pageMarks`, `dimRejected` | локальные |
    | `filterPresets` | объединение по имени без учёта регистра; совпало имя — остаётся локальная; совпал только `id` — предустановке из копии выдаётся новый `id`; сверх 20 — не добавляются, их число показывается в итоге |
  - **Запись** — мутация `restore` по протоколу Ф11 (`pending`). Итоговые `sources`,
    `columns`, `columnOrder` пишутся уже на шаге 1 вместе с `pending: true` (Ф11). На
    шаге 3 — `meta` без `pending`, с `domainCount` по числу записей и новым `rev`. Если
    восстановление прервано, `meta` пересобирается по Ф11 с сохранением этих подписей;
    повтор того же восстановления даёт тот же итог.

### 4.7 Отметки в таблице сайта (проект, 0.2)

**Статус: согласовано 2026-11-23 (решения владельца — в конце раздела), не реализовано.** Запрос
владельца: доработки прямо на страницах ED. Опора — наши идеи из
[collections.md](research/collections.md) и разбор конкурента NameGPS v1.2.1 (2026-11-23, код
только прочитан, не копируется).

**Что у конкурента и что берём.** NameGPS добавляет в таблицу колонку с данными о продажах,
подкрашивает строки (полоса слева + тон фона) и ставит значок с оценкой сразу после ссылки
домена; действий в строке нет — список отобранного только в его боковой панели. Берём форму:
**значок после ссылки домена и полоса у строки**, а не новую колонку. Не берём: новую колонку
(ломает ширины и заголовки сайта), перестановку строк (спорит с сортировкой сайта),
принудительную обрезку колонок сайта, опрос таблицы таймером (у него каждые 500 мс), поиск
«любой `table`» и пути XPath, прокрутку к строке и автоклик «Next» (I2, I3), стили без тёмной
темы.

- **Ф28. Значок домена в таблице.** На странице с распознанной таблицей (Ф1, режим `ready`)
  в ячейку домена **после** ссылки домена ставится наш значок — отдельный хост с closed
  Shadow DOM, стили внутри (как Ф3). Показывает, что домен уже в накоплении, и его статус:
  - сохранён без статуса — нейтральная точка; `shortlist` — звезда; `rejected` — крест;
    `bought` — галочка (те же иконки и цвета, что в боковой панели, Ф13);
  - есть теги или заметка — маленькая метка рядом; подсказка (`title`): «В накоплении ·
    статус · теги · есть заметка»;
  - домен не в накоплении — значка нет (или см. Ф31).
- **Ф29. Полоса и приглушение строки.** У строки домена со статусом `shortlist` — цветная
  полоса слева; `rejected` — строка приглушена (прозрачность ~0,45), но не скрыта: число строк
  на странице остаётся тем же, что показывает сайт. Делается атрибутом `data-eds` на `<tr>` и
  одним нашим `<style>` с селекторами по этому атрибуту; ни один стиль сайта не меняется.
  Выключение — убрать атрибуты и `<style>`.
- **Ф30. Быстрый статус из строки.** Клик по значку (или по месту значка у несохранённого
  домена при наведении на строку) открывает маленькое меню в нашем Shadow DOM: «Отобрать»,
  «Отклонить», «Снять статус». Это клик пользователя по нашему элементу, не по сайту (I2).
  - домен в накоплении → `eds:update` (Ф20);
  - домен не в накоплении → сначала сохраняется **одна эта строка** тем же путём, что «Сохранить
    страницу» (`eds:add` с одной строкой, те же колонки, Ф8), затем `eds:update`. Ошибка
    второго шага показывается в строке статуса панели на странице.
- **Ф31. «Новый» при открытии.** Домены, которых не было в накоплении в момент загрузки
  страницы, помечаются меткой «новый» до перезагрузки страницы — и при автосборе, когда они
  уже сохранены. Видно, что прибавилось с прошлого просмотра того же списка.
- **Ф32. Обновление и выключение.**
  - Значки обновляются по `storage.onChanged` (новый `meta.rev`): одно чтение
    `storage.local.get` записей `d:*` только для доменов этой страницы. Таймеров нет.
  - Настройки (раздел 6, `settings`): `pageMarks` — значки и меню (Ф28, Ф30, Ф31);
    `dimRejected` — приглушение отклонённых (Ф29). Переключатели — в панели на странице и в
    «Данных и резервной копии» боковой панели. Выключение убирает всё вставленное сразу, без
    перезагрузки.
- **Ф33. Границы.**
  - Отметки не меняют того, что читает парсер: у значка нет `<a>` в обычном DOM, текст — только
    в Shadow DOM (`textContent` ячейки не меняется), атрибут `data-eds` парсер не читает.
    Приёмка: разбор таблицы до и после отметок даёт одинаковый результат (Д4, Д7).
  - I6 без изменений: со страницы читается только `#listing`; статусы берутся из хранилища.
  - I1–I3 без изменений: запросов нет, по элементам сайта не кликаем, не прокручиваем.
  - Страница до 200 строк: обновление значков — не дольше 16 мс на кадр на средней машине
    (замер в A8).
  - Тёмная тема — по `prefers-color-scheme`, как панель на странице (Ф3).

**Решения владельца (2026-11-23):**
1. В первую версию входят все четыре: Ф28, Ф29, Ф30, Ф31.
2. Ф30 для несохранённой строки — сохраняется одна эта строка, затем ставится статус.
3. Отклонённые приглушаются (Ф29), не скрываются.
4. `pageMarks` и `dimRejected` по умолчанию включены.

### 5.3 Ячейки статистики
- **Д7.** `textContent` ячейки содержит мусор. Это иконки-ссылки сервисов (`a.favicons`:
  «Majestic.com SEOkicks.de») и выпадающее меню (`ul.kmenucontent`). Пример: колонка `bl`
  в первой строке `deleted-com-p1` целиком даёт `383Majestic.com SEOkicks.de`.
  **Значение = текст ячейки без `.favicons`, `.kmenucontent`, `.smenu`**, пробелы
  нормализуются.
- **Д8.** Значение — **произвольный текст**, сохраняется как есть, без преобразования.
  Список наблюдавшихся форматов неполный:
  - `-` — нет данных, пустая строка;
  - числа: целые, `6.0 K`, `848.8 K`, `6.8 M`;
  - деньги: `898 USD`, `440 USD`, `788 EUR`;
  - даты: `2026-10-18`;
  - **относительное время:** `32 days`, `5h 33m`, `1d 11h 50m`, `Yesterday 14:00`. Оно
    имеет смысл только вместе с моментом захвата (`lastSeen`). Хранится как текст, а
    абсолютное время считается при показе и фильтрации (Ф24);
  - статусы: `available` / `registered` / `Available`, `Deleted`, `Sale`;
  - в `geo_flag` — `PA` (частичное совпадение), в `geo_country_code` — коды стран
    (`JM`, `US`, `GB`), в том числе списком через запятую.

- **Д8а. Точная дата регистрации — исключение из Д8.**
  - В ячейке `creationdate` виден только год (`2025`). Полная дата есть в подсказке
    ссылки: `<a title="Whois Creation Date: 2025-08-06">2025</a>`.
  - Если `title` первой ссылки ячейки точно совпадает с
    `^Whois Creation Date: (\d{4}-\d{2}-\d{2})$`, в `stats.creationdate` сохраняется
    дата `2025-08-06`. Иначе (ячейка `-`, ссылки нет, текст подсказки другой)
    сохраняется текст ячейки по Д7.
  - Год остаётся началом значения, поэтому сравнение и сортировка по году не ломаются.
  - Формат одинаковый на всех 7 фикстурах, где есть эта колонка: deleted p1/p2, keyword
    search, pending delete, GoDaddy, Sedo, Watchlist.
- **Д8в. Дата освобождения из подсказки `whois2` — отдельный ключ `dropped`.**
  - В результатах поиска нет колонки `changes`. Дата освобождения есть только в подсказке
    ячейки `whois2`: `<a title="Dropped 37 days ago (2026-10-13)">Available</a>`.
  - Если `title` первой ссылки ячейки `whois2` совпадает с
    `^Dropped .+ \((\d{4}-\d{2}-\d{2})\)$`, в `stats.dropped` сохраняется
    дата `2026-10-13`. Само значение `whois2` (`Available`) не меняется: по нему работает
    условие «Свободен» (Ф25).
  - Если подсказки нет или формат другой, ключа `dropped` нет.
  - `dropped` — вычисляемая колонка. Она регистрируется в `meta.columns` с
    `label: "Dropped date"` и пустым `title` и попадает в `columnOrder` сразу после
    `whois2`. Поэтому в CSV (Ф17) она выходит обычной колонкой статистики. Парсер
    возвращает её в `columns`, только если подсказка разобрана хотя бы в одной строке
    страницы.
  - Формат снят на `keyword-search` (25 из 25 строк).
- **Д8б. Остальные подсказки ячеек в v1 не сохраняются.** Что в них есть (по фикстурам)
  и почему не берём:

  | Колонка | Подсказка | Значение в ячейке | Почему не берём |
  |---|---|---|---|
  | `bl`, `domainpop` | точное число `1,767` | `1.8 K` | для порогов Ф25 округления до K достаточно |
  | `abirth` | `First seen 2021-12-22, 18 saved results` | `2021` | фильтр Ф25 — по году |
  | `aentries` | `0 saved crawl results` | `0` | дублирует значение |
  | `endtime` | `Time Left: 5 hours, 33 minutes` и с новой строки `2026-11-19 17:23:59 UTC` | `5h 33m` | `5h 33m` от `lastSeen` уже даёт точность до минут (Ф24) |
  | `changetimer` | `Changed 2 hours, 59 minutes ago` | `2h 59m` | даёт только направление отсчёта (Ф24) |
  | `whois2` | `Dropped 37 days ago (2026-10-13)` | `Available` | **берём** — Д8в |
  | `enddate` | `Date is most likely accurate` / `Date can't be determined` | `2026-12-05` | оценка надёжности, в фильтрах не участвует |
  | `geo_*`, `status*`, `price`, `related_cnobi`, `wikipedia_links` | полные названия, `.com available`, `Bid` | коды и числа | пояснения, не новые данные |

  Ссылки меню «Related Links» (`Google site:` и другие) лежат в `.kmenucontent` и
  отбрасываются по Д7. В ячейках `changes` подсказок нет.

### 5.4 Страница и навигация (только чтение)
- **Д9. Пагинация.**
  - Номер страницы берётся из первого `#listing .pageinfo` («Page N of M»).
    - На deleted и в поиске он внутри одного из двух `.listingpager`.
    - На Sedo — прямо в `.pagescode`, без `.listingpager`.
    - **Без логина `.pageinfo` нет:** есть только «About N Domains» и `a.next`.
  - M — с разделителями тысяч (`58,270`): перед преобразованием в число запятые
    удаляются. Если `.pageinfo` нет или текст не разобран, «стр. X из Y» не
    показывается (это не ошибка).
  - Ссылки `a.next` / `a.prev` (`?start=25#listing`) ведут на обычную загрузку нового URL.
    Расширение **никогда не переходит** по ним (I3).
- **Д10. Источник.**
  - `sourceId` = `location.host` + `location.pathname`. Хост нужен, потому что
    публичные и member-страницы имеют разные пути одного списка
    (`/deleted-com-domains/` и `/domains/expiredcom/`).
  - Для `/domain-name-search/` с непустым `q` добавляется `?` +
    `new URLSearchParams({ q }).toString()` (каноничное кодирование): каждый поиск —
    отдельный список. Без `q` или с пустым `q` — без добавки. Предел длины и суффикс для
    длинных `q` — раздел 6, «Общие пределы».
  - `savedsearch_id` и прочие параметры query не сохраняются: `savedsearch_id`
    привязан к аккаунту.
  - `sourceLabel` = `document.title` до первого ` » ` или ` | `:
    - `Deleted .com Domains » ExpiredDomains.net` → `Deleted .com Domains`;
    - `Deleted .com Domains | Now Available…` → `Deleted .com Domains`.

    Для поиска к нему добавляется `: <q>`.
  - Watchlist сайта: `sourceId` = `member.expireddomains.net/domains/watchlist/`,
    `sourceLabel` = `Watchlist Domains`.
- **Д11. Встроенная кнопка копирования сайта.** На страницах с входом и с результатами
  есть `.copyclipboard[data-clipboard-text]` («Copy 25 Domains into your Clipboard»).
  Там полные имена доменов страницы через перевод строки. Без логина и на пустом
  результате её нет.
  - Расширение **не нажимает** эту кнопку (I2).
  - Атрибут можно **читать** как перекрёстную проверку парсера (A3). На 7 фикстурах с
    кнопкой список совпал с `title` ссылок.
  - Сайт и сам умеет скопировать 25 доменов одной страницы. Наша ценность — накопление
    между страницами, колонки статистики и экспорт.
- **Д12. Фильтр и сортировка — с перезагрузкой страницы.**
  - Сортировка — обычные ссылки `?o=…&r=…`.
  - Фильтр — форма `method=post` с `action` на тот же список (`…/#listing`).

  Признаков AJAX-обновления таблицы нет, поэтому С2 в v1 достаточно. Факт снят по
  атрибутам формы; сама форма не отправлялась.

### 5.5 Остаётся непроверенным
- IDN: ни одного примера (Д6). Если пользователь встретит такой домен, нужна фикстура.
- Альтернативные гипотезы вёрстки:
  таблица `table.tbl_main` или `#domainlist`, домен в `button.domain`. **Ни на одной из 9
  страниц не встретились.** Вероятно, это устаревшая вёрстка. В контракт не входят.
- Страница сайта совсем без `#listing` (например, `/faq/`) отдельно не снималась.
  `no_listing` проверяется производной фикстурой (A4).

## 6. Модель данных

```jsonc
// storage.local — запись на каждый домен + общие ключи
{
  "d:example.com": {
    "firstSeen": 1795036674000,               // epoch ms, при первом захвате
    "lastSeen":  1795036780000,               // epoch ms, при последнем захвате
    "lists": ["member.expireddomains.net/domains/expiredcom202611/"], // sourceId (Д10) всех списков, где встречен (Ф8)
    "lastSource": "member.expireddomains.net/domains/expiredcom202611/",
    "stats": { "bl": "383", "abirth": "-", "changes": "32 days", "creationdate": "2025-08-06" }, // key (Д2) → значение (Д7, Д8а); плюс вычисляемый `dropped` (Д8в); снимок последнего захвата (Ф8)
    // пользовательские поля (Ф20–Ф22); захват их не меняет; отсутствуют, пока не заданы
    "status": "shortlist",                    // new | shortlist | rejected | bought; нет поля = new
    "tags": ["drop .com", "клиент А"],        // 0–20, без дублей без учёта регистра
    "note": "проверить историю в архиве"      // ≤ 1000 символов
  },
  "meta": {
    "schema": 2,
    "sources": { "member.expireddomains.net/domains/expiredcom202611/": "Deleted .com Domains" }, // sourceId → sourceLabel
    "columns": { "bl": { "label": "BL", "title": "Majestic External Backlinks, …" } },
    "columnOrder": ["length", "bl", "domainpop"], // порядок первого появления
    "domainCount": 1,                             // для бейджа (Ф12)
    "rev": 42,                                    // +1 на последнем шаге каждой мутации (Ф10, Ф16)
    "pending": false                              // true между шагами 1 и 3 мутации (Ф11)
  },
  "settings": {
    "autoCapture": false, "panelCollapsed": false,
    "pageMarks": true, "dimRejected": true,      // 4.7 (Ф28–Ф32), с 0.2; нет в хранилище → true
    "filterPresets": [{ "id": "p1", "name": "Свежие .com", "filter": { "zones": ["com"], "freshHours": 48 } }], // Ф26, до 20; filter — тип Filter (Ф25)
    "activePreset": "all"                        // встроенные: all (вид по умолчанию), working-drops, working-auctions (Ф26)
  }
}
```

- **Общие пределы — одни для захвата и для восстановления.** Один валидатор в
  `src/shared/`: всё, что может создать захват, проходит проверку Ф27, и наоборот.
  - `sourceId` ≤ 500 символов. Если с `q` (Д10) длиннее, `q` обрезается так, чтобы
    вместе с суффиксом `~<8 hex>` уложиться в 500. Суффикс — FNV-1a 32 от полного `q`,
    поэтому разные длинные поиски не сливаются.
  - `sourceLabel` ≤ 200 символов, `label` колонки ≤ 200, `title` ≤ 1000: при захвате
    обрезаются по кодовым точкам.
  - Ключ колонки — `[a-z0-9_]{1,64}`, кроме `__proto__`, `constructor`, `prototype`.
    Колонка с другим ключом при захвате пропускается и учитывается в `diagnostics`
    (Е1).
  - Значение `stats` ≤ 1000 символов, при захвате обрезается.
- **Почему запись на домен, а не один объект.** Захват страницы пишет ≤ 25 ключей плюс
  `meta` (дважды: маркер `pending` и итог, Ф11), а не переписывает весь массив. Так дешевле по времени и меньше потерь при
  сбое.
- **Размер.** Реальная запись с 27 ключами статистики занимает ~0,7 КБ. 10 000 доменов
  дают ~7 МБ, это близко к квоте `storage.local` в Chrome (10 МБ). Отсюда
  `unlimitedStorage` (I4, без предупреждения при установке). Цифра — оценка по
  фикстурам, проверяется замером в A7.
- **Боковая панель** читает всё одним `storage.local.get(null)` и отбирает ключи `d:*`.
- **Набросок** (`eds:v1`) не выпускался, миграции нет. Ключ `eds:v1` при старте
  удаляется.

## 7. Ошибки и дрейф вёрстки

- **Е1.** `diagnostics` парсера содержит:
  - `code`: `ok` | `no_listing` | `no_table` | `no_domain_column` | `no_rows` | `too_many_rejected`;
  - число строк;
  - число принятых;
  - число отброшенных строк с первыми 3 причинами.

  Строки без `td.field_domain` (например, «no Domains found», Д1а) служебные: они не
  считаются ни строками данных, ни отброшенными. Доля для `too_many_rejected` считается
  только по строкам данных.

  Повтор того же домена на одной странице не считается отброшенным: берётся первая строка.

  Если строк данных нет, `no_rows` и `no_domain_column` различаются так: есть строка с
  ячейкой `td.field_*` (колонки на месте, а ячейки домена нет) — `no_domain_column`; ни
  одной такой ячейки (пустой `tbody` или одна строка «no Domains found») — `no_rows`.
  Нет `th.head_domain` — `no_domain_column` в любом случае.
- **Е2.** Поведение панели по `code`:

  | `code` | Панель |
  |---|---|
  | `no_listing` | Не показывается |
  | `no_table` (`#listing` есть, `table.base1` нет), `no_domain_column`, `too_many_rejected` (отброшено > 20% строк) | «Вёрстка сайта не распознана — сохранение отключено», кнопка неактивна, автосбор пропускает страницу |
  | `no_rows` | «Список пуст» |

- **Е3.** Расширение перезагружено, а старый content script остался на вкладке
  (`Extension context invalidated`). Панель пишет «Обновите страницу».
- **Е4.** Фолбэк «любые ссылки, похожие на домены» запрещён: он сохраняет мусор. В
  наброске это `a[href*="/domain/"]`.

## 8. Кроссбраузерность

Целевые браузеры — Chrome, Edge, Firefox. Один исходный код на WXT (ADR-0003), три сборки:
`wxt build` → `dist/chrome-mv3`, `-b edge` → `dist/edge-mv3`, `-b firefox` →
`dist/firefox-mv2`. Манифест задаётся в `wxt.config.ts` функцией от `browser`, как в
`redirect-inspector`.

- **Chrome / Edge:** MV3, background — service worker. `minimum_chrome_version: "116"`
  только для Chrome, как в остальных расширениях (довод «121 ради `scripts` +
  `service_worker` в одном манифесте» отпал: у каждого браузера свой манифест).
- **Firefox:** MV2 — это поведение WXT по умолчанию, и так собраны все остальные
  расширения 301.st.
  - Background — `background.scripts` (WXT не ставит `persistent: false`, значит
    страница постоянная). Протокол Ф10–Ф11 от этого не меняется: он рассчитан на
    остановку в любой момент.
  - Кнопка — `browser_action` (WXT переводит `action` сам).
  - Права на сайт в MV2 даются через `content_scripts.matches` при установке; ключа
    `host_permissions` в MV2 нет.
  - `browser_specific_settings.gecko`:
    - `id: "expired-domains@301.st"` (шаблон `<slug>@301.st`);
    - `strict_min_version: "140.0"` — с этой версии Firefox понимает
      `data_collection_permissions` (так и в остальных расширениях);
    - `data_collection_permissions: { required: ["none"] }`.
  - Блок `gecko_android` **не добавляется**: Android не тестируется и не заявлен.
- **Background-код** не хранит состояние в глобальных переменных (Ф10) и не использует
  DOM — он должен одинаково работать в service worker и на странице MV2.
- **API:** через `browser` из WXT (`wxt/browser`). `getBytesInUse` не используется.
- **Скачивание из боковой панели** (Blob + `<a download>`) — приёмка в Firefox: A11, и её провал
  **блокирует релиз**. Тихой деградации до буфера обмена нет. Если Blob-скачивание в
  Firefox не работает, есть два пути, оба через ADR:
  - добавить право `downloads` (расширяет I4);
  - сузить объём Firefox-версии.

### 8.1 Требования магазинов (Chrome Web Store, Edge Add-ons, AMO)

- **М1. Единственное назначение.** Описание и функциональность соответствуют одной цели:
  «сохранить домены со страниц, которые вы открыли». Без побочных функций.
- **М2. Обоснование каждого права** (`storage`, `unlimitedStorage`, `sidePanel`, доступ
  content script к сайту). Тексты обоснований хранятся рядом с описаниями (М7).
  `sidePanel`: «список собранных доменов открыт сбоку, пока вы листаете страницы».
  - **Firefox и `unlimitedStorage`.** Право остаётся во всех трёх пакетах (I4), чтобы
    матрица прав была одной. Довод: `storage.local` в Firefox хранится в IndexedDB и без
    права может подпадать под общие квоты и вытеснение **[не проверено]**. Показывает ли
    Firefox для него строку в окне установки, тоже **[не проверено]** — если да, это
    допускается и описывается в обосновании.
- **М3. Раскрытие данных.** Формулировка для политики и анкет: расширение **читает и
  хранит локально** содержимое сайта (списки доменов с колонками) и адрес списка. Никуда
  их не передаёт. Пользователь удаляет их кнопкой «Очистить» или удалением расширения.
  - CWS: в анкете отмечаются категории «Website content» и «Web history» (адреса списков
    и поисковый запрос `q` в `sourceId`), с сертификацией Limited Use. Требования CWS к
    данным касаются и данных, которые обрабатываются только локально.
  - AMO: `data_collection_permissions.required: ["none"]`, потому что данные не
    передаются.
  - Edge: та же формулировка, что для CWS.
  - **Политика конфиденциальности** — общая страница семейства
    `https://301.st/apps-privacy` (решение пользователя: отдельного сайта у расширения
    нет). Её источник — репозиторий `301-ui`, файл `public/apps-privacy.html`. Перед
    подачей в магазины туда добавляются:
    - строка в таблицу приложений: «Expired Domains · Browser extension · Domain rows
      (names and stats columns) and list addresses from expireddomains.net pages you
      open · Locally in your browser only; no network requests»;
    - раздел «Expired Domains Specifics»: что читается (только `#listing` и адрес
      списка, I6), что не читается (аккаунт, email, остальная страница), где хранится,
      как удалить («Очистить», удаление расширения).

    Правка `301-ui` — отдельная задача в том репозитории, не в этом.
- **М4. Без удалённого и обфусцированного кода.** Пакет собирается WXT (Vite), без
  минификации-обфускации сверх стандартной сборки. Для AMO нужен **архив исходников** и
  инструкция сборки, как в `agent-readiness/AMO_BUILD.md`: Node 22, `npm ci && npm run
  zip:firefox`, результат в `dist/firefox-mv2/`. Архив исходников собирает `wxt zip -b
  firefox`; в `zip.excludeSources` — `temp/**`, `.agents/**`, `docs/plans/**`.
- **М5. Название и бренд.** Название — **Expired Domains** (решение пользователя,
  2026-11-19). Это общее название категории доменов, а не бренд сайта
  «ExpiredDomains.net». Чтобы расширение не выглядело официальным продуктом сайта:
  - слитное написание `ExpiredDomains` и домен `.net` в названии не используются;
  - логотип и цвета сайта не используются; иконка (глаз камеры над сеткой глобуса,
    `src/public/icons/icon.svg`) — в цветах 301.st: обод `#4DA3FF`, линза `#111111`,
    глаз `#003682` → `#0055DC` → `#4DA3FF` (решение пользователя, 2026-11-20);
  - в кратком и полном описании стоит фраза «Unofficial. Not affiliated with
    ExpiredDomains.net» (RU: «Неофициальное расширение, не связано с ExpiredDomains.net»).

  Остаточный риск: магазин или правообладатель всё равно сочтут название похожим. Тогда
  запасной вариант — уточнение через тире (например, «Expired Domains — List Saver»),
  без смены кода.
- **М6. Формулировки.** В описании не обещается обход ограничений сайта. Формулировка:
  «сохраняет то, что вы уже видите на экране; не отправляет запросов».
- **М7. Материалы, по магазинам.** Раскладка как в `agent-readiness`: картинки в
  `store-assets/`, тексты в `docs/store-listings/{chrome,edge}/<lang>.txt`,
  `docs/store-listings/firefox/<lang>.md`, `docs/store-listings/reviewer-notes.txt`.
  - **Пакет:** иконки `src/public/icons/{16,32,48,128}.png`, растеризуются из одного
    SVG скриптом в `scripts/` (как `spintax-extension/scripts/make-icons.mjs`).
  - **Картинки магазинов** (2026-11-20): скриншоты снимаются со стенда
    `scripts/store-harness.mjs` (собранная боковая панель и стартовая страница на
    выдуманных доменах, без сайта и аккаунта), плитки 440×280 и 1400×560 — `npm run
    promo` (SVG → 24-битный PNG без альфа-канала). Порядок и карта загрузки —
    `docs/store-listings/submission-guide.md`.
  - **CWS:**
    - скриншоты 1280×800 (без персональных данных);
    - промо-плитка 440×280.
  - **Edge:**
    - логотип 300×300;
    - скриншоты;
    - заметки для сертификации.
  - **AMO:**
    - скриншоты;
    - лицензия;
    - заметки для ревьюера.
  - **Везде:**
    - краткое и полное описание (EN + RU);
    - контакт поддержки `support@301.st`.
- **М8. Сборка пакетов.** `npm run zip:all` (`wxt zip && wxt zip -b firefox && wxt zip -b
  edge`) — три zip и архив исходников. Версия записана в `package.json` и в
  `wxt.config.ts`; их совпадение проверяет `cut-release.yml`. Workflow как в
  `agent-readiness` (2026-11-20): **Cut release** (полная проверка на Linux → тег) →
  **Release** (пакеты, архив исходников и `SHA256SUMS.txt` в GitHub Release) → **Submit to
  stores** (общий `store-submit.yml`; первая подача — вручную из GitHub Release: v0.1.0
  вышел только на GitHub, в магазины первой идёт v0.1.1, Cut release с `submit` = none;
  локальный zip в магазин не загружается).
- **М9. Доступ для ревьюеров.** Без входа сайт таблиц доменов не показывает, а при каждом
  входе с нового устройства присылает код на почту аккаунта. Поэтому общий тестовый
  аккаунт ревьюеру не поможет: код придёт в чужой ящик (решение 2026-11-19 «отдельный
  тестовый аккаунт» заменено 2026-11-20). Нужны:
  - пошаговая инструкция в заметках ревьюеру;
  - просьба зарегистрировать свой бесплатный аккаунт (`/register/`) на любой читаемый
    адрес; для одноразового адреса рекомендован MailBot того же разработчика (расширение в
    Chrome, Edge, Firefox и бот в Telegram): адрес живёт 24 ч, код показывается первой
    строкой. Ссылки на MailBot — только в заметках ревьюеру, не в листинге и не в
    расширении;
  - проверено 2026-11-20: ED принимает адрес MailBot, письмо доходит, аккаунт
    активируется.

### 8.2 Стек и оформление как в остальных расширениях 301.st

## 9. Нефункциональные требования

- **Н1.** Разбор страницы ≤ 50 мс на 25 строк. Время от «Сохранить» до ответа ≤ 300 мс
  при 10 000 доменах в хранилище. Замеряется на реальном `storage.local` с обменом
  сообщениями, а не на объекте в памяти.
- **Н2.** Боковая панель открывается ≤ 500 мс при 10 000 доменах (рендер ≤ 500 строк). На тех же
  10 000:
  - пересчёт выборки при смене любого условия Ф25 — ≤ 100 мс;
  - массовое `update` всех доменов — ≤ 2 с;
  - резервная копия — ≤ 1 с;
  - восстановление — ≤ 3 с.
- **Как мерить Н1 и Н2.** Это цель релиза, а не тест на каждую сборку:
  - Chrome stable на машине разработчика, медиана из 5 прогонов, `performance.now()` в
    странице расширения;
  - чистые функции (фильтр, CSV, резервная копия, слияние) дополнительно меряются в
    vitest на 10 000 синтетических записей как барьер от регрессий: предел — удвоенная
    цель.
  - Н2 — измеряемая цель на приёмочном наборе A7/A13, а не гарантия для любого regex,
    прошедшего ограничения Ф25.
- **Н3. Языки: английский и русский** (решение пользователя, 2026-11-19).
  - `src/public/_locales/{en,ru}/messages.json`, `default_locale: 'en'`.
  - Все строки интерфейса (панель на странице, боковая панель, бейдж, ошибки Е2) — через `t()` из
    `src/shared/i18n.ts`. Строк в коде нет.
  - Название и описание в манифесте — `__MSG_extName__` / `__MSG_extDescription__`.
  - Подписи в кавычках в этом ТЗ («Сохранить страницу», «Не сохранено — повторите»…) —
    русские варианты; английские задаются в `en/messages.json`.
  - Набор ключей `en` и `ru` совпадает — проверяется тестом.
  - Заголовки CSV и имя файла не локализуются (Ф17, Ф19).
- **Н4. Зависимости.** Сборка — WXT. Зависимостей в рантайме нет (как в
  `redirect-inspector`: «Zero runtime dependencies»). Dev-зависимости: WXT, TypeScript,
  Biome, vitest, DOM-реализация для тестов, растеризатор иконок.
- **Н5.** `npm run check` (`tsc --noEmit`, `biome check`, `vitest run`) проходит без
  ошибок.

**A6 — надёжность очереди:**
- два перекрывающихся `add` дают корректное объединение;
- `add`, отправленный после `clear`, применяется после него;
- при подменённом `storage.local.set`, который отклоняет запись, отправитель получает
  `error`;
- **обычный старт** (`meta.pending` нет) → `ensureReady` идёт быстрым путём: читаются
  только `meta` и `settings`, полного чтения `d:*` нет (проверяется подсчётом вызовов
  `get`);
- **частичное состояние:** вручную записана часть `d:*` при `meta.pending = true` (или
  `meta` нет совсем) → после перезапуска worker `meta` в точности пересобрана по Ф11:
  - лишние `sources` и `columns` удалены;
  - `columnOrder` восстановлен;
  - `domainCount` верен;
- перезапуск worker одновременно с `add` → `add` выполняется после `ensureReady`, его
  данные в `meta` не потеряны;
- боковая панель, открытая при «холодном» worker, показывает уже сверенное состояние;
- worker остановлен до ответа → панель показывает «Не сохранено». Повторный захват не
  плодит дублей, `firstSeen` не меняется;
- прерванный `clear` (удалена часть `d:*`) → после перезапуска `meta` соответствует
  остатку;
- `delete` и `clearList` (Ф15а): удаляются только нужные записи, `meta` пересобрана по
  остатку; у `clearList` домен из других списков остаётся с полями пользователя,
  `lastSource ∈ lists`; прерванное `delete` оставляет `pending`, перезапуск сверяет `meta`;
- то же — с перезагрузкой background-страницы в Firefox (`about:debugging` → «Перезагрузить»);
- **пустое хранилище** → первый `add` создаёт `meta` и `settings` по умолчанию, `rev`
  растёт;
- **обновление открытого списка (Ф16):** во время `add` на 25 доменов при 10 000 в
  хранилище открытый список перечитывает хранилище ровно один раз (подсчёт вызовов
  `get(null)`) и ни разу не показывает состояние с `pending`; `update` из другой копии
  интерфейса (боковые панели в двух окнах браузера) обновляет обе; `clear` при открытом
  списке → список пуст, ключ `meta` есть, `rev` вырос.
